# STM32 기반 저전력 CAN 통신 스마트 모터 제어 노드 시스템
(Smart Motor Node Controller with Low-Power CAN & Robust Fault Protection)

## 📌 프로젝트 개요
본 프로젝트는 **STM32F446RE MCU**를 활용하여 전기차(EV) 및 스마트 팩토리 분산 제어 환경에서 요구되는 고신뢰성, 저전력 특성을 갖춘 **스마트 모터 제어 노드(Smart Motor Node)**를 개발한 프로젝트입니다. 

단순히 모터를 구동하는 것을 넘어, 하드웨어적 제약 사항과 통신 지연을 고려한 아키텍처 설계를 반영했습니다. **[저전력 수면 및 하이브리드 기상] ➔ [CAN 통신 자가 진단] ➔ [고신뢰성 와치독 관리] ➔ [하드웨어 스톨(Stall) 방어 퓨즈] ➔ [정밀 PID 폐루프 속도 제어]**로 이어지는 유기적인 순차적 상태머신(State Machine) 구조를 임베디드 C 기반으로 완벽하게 구현했습니다.

## 🛠️ 핵심 기술 스택 및 구현 기능

### 1. 전력 최적화 관리 (Low-Power Power Management)
* **STOP 모드 진입 및 가사 상태 구현**: 배터리 기반 노드 시스템의 전력 소모를 최소화하기 위해, 메인 연산이 종료되면 CPU와 핵심 클럭 소스를 전면 중단시키는 `HAL_PWR_EnterSTOPMode` 시스템 다운 스택을 설계했습니다.
* **하이브리드 기상 메커니즘 (WFI)**: 독립식 하드웨어 타이머인 **RTC 알람 인터럽트(주기적 3초 기상)**와 사용자가 물리적으로 작동시키는 **EXTI 외부 인터럽트(파란색 유저 버튼 누름 즉시 기상)**를 연동하여 가사 상태에서 즉각 복구되는 하이브리드 인터럽트 대기 구조(`WFI`)를 구축했습니다.
* **동적 클럭 라인 복구**: STOP 모드에서 탈출할 때 기본 내부 느린 클럭으로 고정되는 후유증을 방지하기 위해, 깨어나자마자 최우선 순위로 메인 시스템 클럭 서킷을 84MHz 최고 속도로 재정렬하는 `SystemClock_Config()` 루틴을 포함하여 타이밍 크리티컬한 모터 동작 오차를 차단했습니다.

### 2. 분산 네트워크 아키텍처 (CAN 통신 모듈)
* **bxCAN 컨트롤러 자가 진단 (Loopback Mode)**: 다중 노드 통신망 구축 전, 펌웨어 수준의 프로토콜 파싱 유효성을 독립 검증하기 위해 칩 내부에서 송수신을 처리하는 CAN Loopback 아키텍처를 설계했습니다.
* **비동기 인터럽트 수신 콜백**: 메인 스레드의 연산 흐름을 방해하지 않고 CAN 버스로부터 구동 명령(`target_velocity`, `mode` 등)이 도착하면 즉각 반응하도록 `HAL_CAN_RxFifo0MsgPendingCallback` 인터럽트 서비스 루틴(ISR)을 구축하여 실시간 메시지 동기화를 완료했습니다.

### 3. 고안정성 Failsafe 아키텍처 (Watchdog & Smart Delay)
* **독립형 와치독 타이머 (IWDG)**: 하드웨어 노이즈나 소프트웨어 데드락으로 인한 메인 시스템 먹통 현상을 하드웨어 레벨에서 감시하고 강제 리셋하는 독립 퓨즈 구조를 세팅했습니다.
* **타임 슬라이싱 기반 와치독 피딩 (Smart Delay)**: 모터가 정방향/역방향으로 동작하며 수 초간 머무르는 블로킹(Blocking) 딜레이 구간(`HAL_Delay`) 동안 시스템 감시견이 리셋을 터뜨리는 현상을 방지하기 위해, 대기 시간을 10ms 단위로 잘게 쪼개어 대기 루프 내에서 지속적으로 `HAL_IWDG_Refresh`를 주입하는 지능형 피딩 알고리즘을 설계했습니다.

### 4. 하드웨어 스톨(Stall) 방어 퓨즈 로직 (Software-Defined Fuse)
* **모터 구속 감지 및 강제 셧다운**: 고무 바퀴나 모터 암이 물리적 방해물에 걸려 강제로 정지하는 스톨(Stall) 상황 시 기어박스 파손이나 코일 소실을 막기 위한 방어막을 구축했습니다.
* **상태 비교 감시 알고리즘**: 모터 드라이버에 공급되는 전기 에너지 출력 지표인 `PWM Duty` 값은 80% 이상 최고치를 향해 폭증하는데, 실제 하드웨어 엔코더 피드백 수치(`current_rpm`)가 5 RPM 미만으로 떨어지는 모순된 비정상 상태를 매 10ms마다 카운팅합니다. 이 불일치 상태가 0.5초 이상 지속되면 시스템 치명상 위험으로 간주하고, 드라이버 소자를 완전히 차단(`motor_fault = 1`)하며 `[FATAL ERROR]` 세이프티 정지를 수행하는 고신뢰성 안전 소프트웨어를 완성했습니다.

### 5. 정밀 폐루프 속도 제어 (Closed-Loop PID Control)
* **하위 분업화 타이머 서킷 설계**: 
  * `TIM1`: 모터 드라이버(TB6612FNG 규격 대응) 입력단에 정밀 전력을 쏴주는 PWM Generation 모듈 배치.
  * `TIM8`: 모터 축과 연동된 물리 엔코더의 A상/B상 구동 펄스를 하드웨어 레벨에서 사배주(`4x`) 디코딩 카운트하는 Quadrature Encoder 모드 배치.
  * `TIM3`: 완벽한 샘플링 시간(10ms 주기)을 하드웨어적으로 보장하는 타임베이스 인터럽트 서킷 배치.
* **속도 방어 및 PID 튜닝**: 마찰이나 부하를 만나 속도가 급락할 때 이를 원상복구 하려는 P(비례), I(적분), D(미분) 연산을 `TIM3` ISR 내부에 탑재하여 완벽한 '척수 반사형' 로컬 폐루프 속도 제어기를 구현했습니다. N20 모터의 기어 내부 정지 마찰력을 즉각 돌파하고 손가락 압력을 견뎌내도록 제어 계수를 매운맛(`Kp = 20.0f, Ki = 10.0f, Kd = 0.0f`)으로 튜닝하여 강인한 토크 유지력을 확보했습니다.

## 📈 트러블슈팅 및 디버깅 로그 (Troubleshooting)

### 🚨 Issue 1: 통짜 딜레이 구간에서의 와치독 강제 시스템 리셋 현상
* **증상**: 오픈루프 구동 테스트 시 정방향 3초 대기 구간(`HAL_Delay(3000)`)을 지나갈 때 다음 시퀀스로 넘어가지 못하고 MCU가 계속 무한 재부팅되는 현상 발생.
* **원인**: `HAL_Delay`가 실행되는 동안 CPU가 블로킹 상태에 빠져 독립 감시 타이머(`IWDG`)에 주기적으로 피딩(Refresh) 신호를 주지 못해, 와치독이 시스템 데드락으로 판단하고 리셋을 터트림.
* **해결**: 통짜 3000ms 대기를 10ms 단위의 `for` 루프 대기로 잘게 쪼개고, 쉬는 시간마다 `HAL_IWDG_Refresh(&hiwdg);` 코드를 강제 삽입하여 3초간 모터를 정상 구동하면서도 안정적으로 개밥(Feeding)을 주는 구조로 우회 해결.

### 🚨 Issue 2: 스톨(Stall) 방어 로직 설계 후 바퀴를 꽉 잡아도 시스템 차단이 안 되는 현상
* **증상**: 모터 바퀴를 손으로 강하게 틀어막아 구속 상태를 만들었음에도 `Update_Motor_Drive` 내부의 `[FATAL ERROR]` 셧다운 퓨즈가 끊어지지 않고 계속 동작함.
* **원인**: 테스트 당시 코드 구조가 모터 속도를 고정 출력(PWM 2100)으로만 내보내는 오픈루프 구조였음. 초기 방어막 발동 조건이 `if(pwm_value > 3300)`으로 설정되어 있어 인가된 전압 에너지 지표가 퓨즈 작동 가이드라인(3300)을 원천적으로 넘지 못해 조건문 통과 실패.
* **해결**: 임시 디버깅을 위해 방아쇠 허들 조건을 테스트 출력 레벨에 맞게 `if (pwm_value > 1500 && fabs(current_rpm) < 15.0f)`로 헐렁하게 조정하여 0.5초 구속 시 즉각 전원이 차단되는 하드웨어 세이프티 퓨즈의 논리적 동작 완벽 검증 완료.

### 🚨 Issue 3: 메인 스레드와 타이머 인터럽트 간 엔코더 카운터 리셋 충돌 (사공이 두 명인 버그)
* **증상**: 진짜 PID 모드를 켜기 위해 `TIM3` 주기적 인터럽트를 활성화하자, 속도 연산용 RPM 피드백 데이터가 비정상적으로 요동치거나 0으로 주저앉으며 모터 제어가 널뛰는 기괴한 현상 발생.
* **원인**: 메인 루프의 `for`문 내부와 `TIM3` 인터럽트 서비스 루틴(ISR) 두 곳 모두에서 `Get_Motor_RPM()`을 동시에 마구잡이로 호출하고 있었음. 해당 함수 내부에는 엔코더 카운터를 리셋하는 `__HAL_TIM_SET_COUNTER(&htim8, 0)` 로직이 존재하여, 인터럽트가 읽기도 전에 메인이 카운터를 초기화해 버리는 치명적인 리소스 데이터 레이스(Data Race) 발생.
* **해결**: 메인 루프 내부의 모터 직접 제어 및 RPM 읽기 코드를 완전히 제거하고, 메인은 오직 지시자로서 전역 변수인 `target_rpm` 값만 통신망을 통해 업데이트하도록 아키텍처 다이어트 단행. 실제 속도 계측 및 PID 연산 집행은 오직 `TIM3` 하드웨어 인터럽트 스레드 단 한 곳에서만 전담하도록 비동기식 독립 분업 구조 설계로 완벽 해결.

### 🚨 Issue 4: Target RPM을 100으로 설정했으나 모터가 구동력을 잃고 웅~ 소리만 내는 현상
* **증상**: 정밀 제어 모드 진입 후 목표 속도를 100 RPM으로 지정했으나 기어가 걸린 듯 돌지 못하고 정지 마찰력을 뚫지 못함.
* **원인**: 기본 설정된 PID 튜닝 상수(`Kp = 1.0, Ki = 0.5`)가 너무 순한 맛이어서 오차가 100이어도 인가되는 PWM 시작 전압이 100(전체 4199 중 약 2.3%)에 불과함. N20 소형 기어드 모터의 물리적 내부 기어 정지 마찰력을 이겨내기엔 전원 인가량이 턱없이 부족하여 누적 시간만 끌었던 것임.
* **해결**: 초기 기동 시 마찰력을 단숨에 폭파할 수 있도록 비례 및 적분 제어 계수를 대폭 펌핑(`Kp = 20.0f, Ki = 10.0f`)하여 입력 즉시 힘차게 돌고 외부 압력을 단단히 방어해 내는 강인한 PID 제어 튜닝 완료.

## 💡 결론 및 향후 확장 계획 (Next Steps)
본 시스템은 단일 MCU 내부에서 자가 통신 진단, 스마트 전력 모드 체인지, 기계 파손 보호 가드가 유기적으로 엮인 하이엔드급 모터 구동 모듈 베이스라인을 완성했습니다. 

향후 3.3V 전용 CAN 차동 번역기 모듈인 **SN65HVD230 트랜시버**를 물리적으로 추가 장착하고, 기 확보한 보유 부품인 **아두이노 + MCP2515 CAN 모듈 조합**과 버스로 연결할 예정입니다. 이를 통해 3.3V 아키텍처(ARM Cortex-M4)와 5V 아키텍처(AVR) 간의 실물 **'이기종 다중 노드 CAN 통신 네트워크망'**을 구축함으로써 차량용 분산 제어 시스템 포트폴리오를 완벽하게 고도화할 계획입니다.
