## 📌 프로젝트 개요
본 프로젝트는 **STM32F446RE MCU**를 활용하여 전기차(EV) 및 스마트 팩토리 환경에서 요구되는 고신뢰성, 저전력 특성을 갖춘 **스마트 모터 제어 노드(Smart Motor Node)**를 개발한 프로젝트입니다.

단순히 모터를 구동하는 것을 넘어, 하드웨어적 제약 사항과 통신 지연을 고려한 아키텍처 설계를 반영했습니다. **[저전력 수면 및 모닝콜 기상 동기화] ➔ [CAN 통신 망 구축] ➔ [하드웨어 노이즈 철벽 방어] ➔ [고신뢰성 와치독 및 스톨 방어 퓨즈] ➔ [정밀 PID 폐루프 제어]**로 이어지는 유기적인 순차적 상태머신(State Machine) 구조를 임베디드 C 기반으로 완벽하게 구현했습니다.

## 🛠️ 핵심 기술 스택 및 구현 기능

### 1. 전력 최적화 관리 (Low-Power Power Management)
* **SLEEP 모드 진입 및 가사 상태 구현**: 초기 극단적 절전을 위한 `STOP` 모드 설계에서 발생하는 '클럭 복구 지연(통신 프레임 유실)' 문제를 극복하기 위해, CPU 코어의 연산만 정지시키고 주변장치(CAN)의 수신 감도는 살려두는 **`SLEEP Mode (WFI)`**로 아키텍처를 고도화했습니다.
* **통신 기반 즉각 기상 메커니즘**: 마스터(아두이노)가 보내는 첫 번째 더미 프레임(모닝콜)을 STM32의 `HAL_CAN_RxFifo0MsgPendingCallback`이 감지하는 즉시, 클럭 재설정 오버헤드 없이 시스템을 깨워 본 명령을 수신할 준비를 마칩니다.

### 2. 이기종 분산 네트워크 아키텍처 (CAN Communication)
* **실물 CAN 통신망 구축**: 내부 Loopback 진단 단계를 넘어, **SN65HVD230 트랜시버(3.3V)**와 **아두이노 + MCP2515 모듈(5V)**을 버스로 연동했습니다. 기존 내부 충돌이 발생하던 PA11/12 핀 대신, **PB8/PB9 핀(AF9)**으로 하드웨어를 재배치하여 물리적 통신망을 완성했습니다.
* **필터 완전 개방 (Open Mask)**: 디버깅 단계에서의 프레임 유실을 방지하기 위해 Filter Bank 설정을 전면 개방(`0x0000`)하여 모든 프레임을 수신 처리합니다.

### 3. 하드웨어 전원 무결성 확보 (Hardware Stability)
* **공통 접지(GND Sharing)**: 서로 다른 전원을 사용하는 아두이노와 STM32 간의 CAN 통신 기준 전압을 통일하기 위해 GND를 단일 라인으로 완벽 통합했습니다.
* **전원 간섭 소자 제외 (Capacitor Removal)**: 초기 노이즈 바이패스 목적으로 배치했던 커패시터가 전원 인가 순간
### 4. 고안정성 Failsafe 아키텍처 (Watchdog & Smart Delay)
* **독립형 와치독 타이머 (IWDG)**: 하드웨어 노이즈나 데드락으로 인한 먹통 현상을 감시하고 강제 리셋하는 독립 퓨즈 구조를 세팅했습니다.
* **타임 슬라이싱 기반 와치독 피딩**: 통짜 딜레이(`HAL_Delay`) 구간 동안 리셋이 터지는 현상을 막기 위해, 대기 시간을 10ms 단위로 쪼개어 지속적으로 `HAL_IWDG_Refresh`를 주입하는 지능형 피딩 알고리즘을 설계했습니다.

### 5. 하드웨어 스톨(Stall) 방어 퓨즈 로직 (Software-Defined Fuse)
* **모터 구속 감지 및 강제 셧다운**: 모터가 물리적 방해물에 걸리는 스톨(Stall) 상황 시 기어 파손을 막는 방어막입니다.
* **상태 비교 감시 알고리즘**: PWM Duty 값이 폭증하는데 실제 피드백 수치(`current_rpm`)가 바닥을 기는 불일치 상태가 0.5초 이상 지속되면, 드라이버 출력을 즉시 차단(`Update_Motor_Drive(0.0f)`)하고 `[FATAL ERROR]` 셧다운 모드로 진입합니다.

### 6. 정밀 폐루프 속도 제어 (Closed-Loop PID Control)
* **하위 분업화 타이머 서킷 설계**: 
  * `TIM1`: 모터 드라이버용 PWM Generation 모듈.
  * `TIM8`: 물리 엔코더의 펄스를 4배수(`4x`)로 디코딩하는 카운터 모드.
  * `TIM3`: 완벽한 샘플링 시간(10ms 주기)을 보장하는 타임베이스 인터럽트.
* **비동기식 Data Race 해결 및 PID 튜닝**: 메인 스레드와 타이머 간의 리소스 충돌을 없애고, N20 모터의 내부 정지 마찰력을 즉각 뚫어낼 수 있도록 제어 계수를 대폭 강화(`Kp = 20.0f, Ki = 10.0f`)하여 강인한 토크를 확보했습니다.

## 📈 트러블슈팅 및 실전 디버깅 로그 (Troubleshooting)

### 🚨 Issue 1: 극단적 절전 모드(STOP) 기상 시 CAN 프레임 유실
- **증상**: STOP 모드 해제 시 클럭 복구 딜레이로 인한 명령 프레임 유실.
- **해결**: CPU만 재우는 **`SLEEP` 모드**로 변경 및 **모닝콜용 더미 프레임(0x123)**을 선송신하여 수신율 100% 확보.

### 🚨 Issue 2: 커패시터 돌입 전류(Inrush Current)로 인한 주변 모듈 전원 다운 현상
- **증상**: 전원단에 커패시터를 연결하자, 전원이 켜지는 순간 커패시터가 순간적으로 전류를 과도하게 잡아당기는 쇼트성 현상이 발생. 이로 인해 시스템 전체 전압이 급격히 떨어지면서 주변 CAN 통신 모듈 및 이기종 보드들의 전원이 통째로 먹통이 되거나 맛이 가는 현상 발생.
- **해결**: 기생 오버헤드와 Brown-out(전압 강하)을 유발하던 **커패시터를 회로에서 완전히 제외(Removal)** 조치함. 불필요한 소자 제거 후 돌입 전류로 인한 전원 간섭 및 다운 현상이 완벽히 소멸되었으며, 모든 노드가 정상 전압 하에서 안정적으로 구동됨을 확인 완료.

### 🚨 Issue 3: 통짜 딜레이(HAL_Delay) 구간 내 와치독 강제 리셋
- **증상**: 긴 블로킹 딜레이 구간에서 IWDG 리셋 발생.
- **해결**: 10ms 단위 쪼개기 루프 및 `HAL_IWDG_Refresh` 주입으로 해결.

### 🚨 Issue 4: 스톨(Stall) 방어 로직의 방아쇠 조건 오류
- **증상**: 물리적 구속 시 퓨즈 미작동.
- **해결**: 허들 조건(`pwm_value > 1500 && fabs(current_rpm) < 15.0f`)으로 재조정하여 동작 검증 완료.

### 🚨 Issue 5: 타이머/메인 스레드 간 엔코더 카운터 리셋 충돌 (Data Race)
- **증상**: PID 활성화 시 RPM 데이터 요동 및 제어 널뛰기.
- **해결**: 메인 루프에서 카운터 직접 수정 로직 삭제, **TIM3 ISR 전담 구조**로 비동기화 완료.

### 🚨 Issue 6: N20 모터 내부 정지 마찰력 극복 실패
- **증상**: 초기 기동 시 모터 구동력 부족.
- **해결**: PID 상수(`Kp=20.0f, Ki=10.0f`) 상향 조정으로 강인한 토크 확보.
